# coOS 產品願景 (Product Vision)

**版本**:1.0

## 一句話定位

coOS 是一款**結合多智能體 AI、遊戲化機制與薩提爾冰山心理模型**的個人目標管理系統,透過邊緣-雲端協同推論在絕對隱私下實現深層心理覺察。

## 它與其他生產力工具的本質差別

傳統工具依賴**意志力**,失敗模式是動力耗竭。coOS 設計奠基於**混合主動式人機互動 (Mixed-Initiative HCI)**,失敗模式是設計缺陷 (而設計缺陷可以修正)。

## 六大支柱

### 1. 半自動捕捉與微摩擦力反思

「全手動紀錄」→ 系統被動監聽生成「反思草稿」→ 強制核准機制保留心理所有權。

關鍵悖論:**不能完全自動,也不能完全手動**。論文依據 R08。

### 2. 視覺化成就與多巴胺刺激

利用「不確定性盲盒」+「即時回饋」,但**僅限於使用者主動觸發的動作**。論文依據 R09 (防範病態使用)。

### 3. 身分邊界

運用「自我複雜度」概念,角色切換時 UI、AI 人設、資料沙盒全數隔離。論文依據 R03 (人設一致性) + 架構文件 (Role_ID 沙盒)。

### 4. 擬真社會承諾與同理心制約

具備固定人設的 AI 專家引發「不願辜負」的責任心。論文依據 R03 + R05 + R09。

**邊界**:不可走向 Replika 式的病態依附 (R09 §3.3)。

### 5. 社會情懷與同儕互相依賴

XP 質押對賭 + 公開承諾 + 社群驗證閉環。論文依據 R01 (Dropout 危機後的安全機制)。

### 6. 極致隱私的邊緣-雲端協同

核心敏感資料絕不上雲,本地壓縮為意圖向量,雲端僅生成「語意草圖」。論文依據 R07 (POST 框架 + Eguard + PRISM)。

## 受眾

主要受眾為:**自主學習者 + 軟體工程師 + 學術研究者**。這群人有三個共通特徵:

1. 重視隱私 (願意接受隱私換取深度)
2. 有 IDE / GitHub 等可被監聽的數位足跡
3. 對「假同理心」高度敏感 (R05 §諂媚效應)

## 不是什麼

- ❌ **不是聊天機器人**。聊天只是輸入介面,不是產品價值。
- ❌ **不是 Notion / Obsidian 競品**。我們不存儲使用者的內容,我們建模使用者的狀態。
- ❌ **不是健康追蹤器**。沒有硬體感測,絕不引入攝影機/定位/手環。
- ❌ **不是無痛工具**。我們刻意設計微摩擦力 (R08)。

## 商業模式 (暫定)

- 個人版:免費 (本地優先)
- Pro 版:雲端同步 + 多裝置 + 較高 Gemini API 配額
- 教育/企業版:私有部署 + 多人協作社群

## 衡量成功的指標

| 指標 | 目標 (MVP 後 6 個月) | 反指標 |
| ---- | -------------------- | ------ |
| Week 4 留存率 | ≥ 40% | 高留存但 mood_score 持續下降 (= 上癮) |
| 平均每日反思時長 | 3~7 分鐘 | < 1 分鐘 (= 無腦點擊) 或 > 15 分鐘 (= 過度) |
| Persona 一致性分數 | ≥ 0.85 (ARPM 評分) | 漂移到通用 AI 語氣 |
| 對外洩漏的 PII 事件 | 0 | 任何 ≥ 1 都是 P0 事故 |
| 觸發 CARE 安全機制次數 | 每 1000 對話 < 5 | (絕對標準,不可低於) |

## 反 KPI (Anti-KPI)

以下指標的「增長」不是好事,**反而是警訊**:

- Gacha 抽卡次數爆增 → 觸發 RISK-09 病態使用
- 連續登入天數很高但 mood_score 低 → 觸發 RISK-10 Gaslighting 感
- Persona 訊息平均長度持續下降 → Persona 退化為通用 AI

## 治理原則

當功能設計、商業目標、心理健康三者衝突時:

**心理健康 > 隱私 > 學術依據 > 產品功能 > 商業指標**

這個順序在團隊任何會議上不可被推翻,除非全員 + 倫理顧問共識。
