## 3. 除錯紀錄與整合風險稽核 (Debugging & Integration Risks Audit)

### 關鍵除錯紀錄 (Debugging Logs)

#### 1. Windows cp950 與 UnicodeDecodeError
- **問題現象**: 在 Windows 環境下執行 Alembic 遷移或讀取 ini 檔案時，拋出 `UnicodeDecodeError: 'cp950' codec can't decode byte...`。
- **原因分析**: `alembic_local.ini` 包含非 ASCII 字元（如 Em Dash `—` 作為註解分隔符），而 Windows 預設 locale 為 cp950。
- **解決方案**: 將設定檔中的註解與文字全部改為純 ASCII，並在程式碼讀取檔案時明確指定 `encoding="utf-8"`。
- **衍生規則**: Windows 開發環境下，設定檔與新檔案應避免非 ASCII 字元。

#### 2. Pydantic Settings & Alembic env.py 插值衝突
- **問題現象**: 執行 Alembic 時拋出 `InterpolationMissingOptionError`。
- **原因分析**: `configparser` 預設會將 ini 檔中的 `%` 字元視為變數插值語法。當資料庫連接字串或密碼中含有 `%` 時會解析失敗。
- **解決方案**: 避免在 ini 中直接配置資料庫 URL，改在 `env.py` 中透過環境變數動態解析並注入到 `context.configure`。

#### 3. pytest 失敗 stack trace 過長導致 Token 耗盡
- **問題現象**: 在 pytest 失敗時，Claude Code 會將數百行的錯誤 stack trace 完整讀入 context，造成巨大的 token 浪費與上下文污染。
- **解決方案**: 改用 `pytest -v 2>&1 | tail -20` 快速查看結論，必要時才用 `grep` 展開。
