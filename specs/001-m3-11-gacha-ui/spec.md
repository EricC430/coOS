# Feature Specification: M3.11 遊戲化抽卡與視覺合成模組 (Gamification Gacha & Visual Studio)

**Feature Branch**: `001-m3-11-gacha-ui`  
**Created**: 2026-10-19  
**Status**: Clarified & Ready for Planning  
**Input**: 實作專案的 M3.11 模組：支援生成背景圖片、生成物體圖片、編輯背景圖片疊加物體圖片（畫布合成）、實作盲盒抽獎功能，並綜合原 SPEC 核心原則（即時開獎、防沉迷冷卻、隱藏成就零洩漏、無預警驚喜彈窗與焦慮推播門禁）。

## Clarifications

### Session 2026-10-19
- Q: 針對「使用免費資源的圖片 LLM 生成器進行附加綜合」，您偏好採用哪種 AI 融合重繪架構與免費服務來源？ → A: 採雙軌混合架構：背景與物件資產獨立分開；背景生成需「背景場景描述」，物件生成需「物件語意特徵」。在背景上即時排版拖曳物件作為底稿，點擊「放置」時呼叫免金鑰免費服務（如 Pollinations.ai / HuggingFace 免費端點）執行 Image-to-Image 圖生圖融合背景與物件光影；若網路失敗自動保留 2D 畫布成果。
- Q: 當使用者點擊「放置」並完成 AI 圖生圖融合後，畫布上的物體圖層應該如何處理？ → A: 採非破壞性圖層保留模式（Option A）。AI 融合圖作為成果展示與匯出，畫布仍保留各物件圖層（坐標/大小/角度）。使用者可隨時微調物件位置再次點擊「放置」，保有完全的復原與編輯彈性。
- Q: 使用者自訂生成的背景與物體圖片，是否應該納入盲盒抽獎池中被隨機抽取？ → A: 採複合混合獎池機制（A+B+C）：抽獎池預設由系統精選官方資產組成（保證美術品質與稀有度階層）；使用者自訂生成作品預設直接入庫，並提供勾選「投入抽獎池」，使後續抽獎有機會抽中自創資產；介面支援切換「精選獎池」與「自創混合獎池」。
- Q: 當使用者輸入「背景場景描述」或「物件語意特徵」進行免費 AI 生成時，系統是否應該自動對 Prompt 進行美學品質與風格增強修飾？ → A: 採現代自然語言完整句式增強範本（Option A 升級版）。系統嚴禁堆疊碎片化標籤（如 8k, masterpiece），而是將使用者輸入動態重構為結構完整、細節具體的自然語言句式（包含主體細節、環境光影、景深透視，物件去背採用純淨單色無雜物陳列之句式描繪），並在進階面板中透明呈現。
- Q: 當使用者在畫布完成「放置」並滿意成果後，該合成圖片除了供下載檔案外，在 coOS 系統內部應該如何儲存與應用？ → A: 採本地自訂主題庫與一鍵套用桌面背景（Option A）。合成場景（含底圖、圖層坐標與 AI 融合圖）持久儲存於本地，支援管理多套自訂佈置場景，並可一鍵套用為 coOS 桌面主背景，同時提供單次 PNG/WebP 檔案下載匯出。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - XP 盲盒抽獎與開獎系統 (Priority: P1) 🎯 MVP

作為一名在 coOS 累積 XP 的使用者，我希望消耗日常賺取的 XP 進行變動比例的盲盒抽獎，隨機抽得精美背景圖片（Backgrounds）或獨立物件/徽章裝飾（Objects/Badges），並能自由切換「官方精選池」與「自創混合池（含自己投入獎池的作品）」，抽獎時立即獲得開獎動畫與 Toast 通知，享受正向成就回饋。

**Why this priority**:
抽獎功能是整個模組的經濟與獎勵循環核心。必須嚴格保證 **L1 即時慶祝**（不走 M3.9 Defer 延遲），同時落實 60 分鐘內最多 5 次抽獎的連續冷卻門禁，防止賭博式成癮行為 [R09 §3.3, RISK-04, RISK-09]。支援混合獎池讓自創資產具備二次抽取的驚喜感。

**Independent Test**:
渲染 `GachaDrawButton`，模擬使用者點擊抽獎：驗證向後端發出抽獎請求，扣除對應 XP，並立即於前端顯示 `GachaResultToast`（無 `data-defer-strategy` 延遲屬性）。連續抽獎 5 次後，驗證按鈕自動鎖定禁用並顯示冷卻警示。測試切換「自創混合池」時，獎池候選項目包含已標記為投入獎池之自創作品。

**Acceptance Scenarios**:
1. **Given** 使用者持有充足 XP（>= 100 XP），**When** 點擊「盲盒抽獎」，**Then** 發送請求至後端抽獎端點，立即彈出開獎 Toast 展示抽得之背景或物件（含稀有度光效），扣除 100 XP，並將物品存入使用者收藏庫。
2. **Given** 使用者切換為「自創混合池」且有自製作品設定為入池，**When** 執行抽獎，**Then** 有機率隨機抽得使用者過去生成的自創背景或物件。
3. **Given** 使用者 XP 餘額不足（< 100 XP），**When** 檢視按鈕，**Then** 按鈕處於禁用狀態，並提示「需要 100 XP（餘額不足）」。
4. **Given** 使用者在 1 小時內已抽獎達 5 次，**When** 再次點擊抽獎，**Then** 按鈕強制進入冷卻鎖定，並顯示滑動視窗剩餘冷卻時間提示。
5. **Given** 後端 API 異常或網路中斷，**When** 抽獎請求失敗，**Then** 彈出「抽獎失敗，XP 未扣除」通知，前端嚴格禁止以 `Math.random()` 偽造中獎結果。

### User Story 2 - 背景圖片生成功能 (Priority: P2)

作為一名想要打造個性化工作空間的使用者，我希望能夠輸入「背景場景描述」（例如：「安靜的賽博龐克研究室，窗外有霓虹雨夜與遠景大樓」）並選取風格主題，系統透過自然語言具體句式增強 Prompt，生成高質感的專屬背景圖片，並保存至我的背景庫，且可自由勾選是否「投入抽獎池」。

**Why this priority**:
背景圖片是視覺合成的基底畫布，自訂生成賦予使用者高度自主性與創造力，強化對系統的心理擁有感 [R08: IKEA 效應 §VI.1]。採用具體連續句式而非碎片化標籤，能顯著提升現代生圖模型的構圖質感與空間氛圍。

**Independent Test**:
渲染 `BackgroundGeneratorModal`，輸入「背景場景描述」並點選風格模板後點擊「生成背景」，驗證底層組裝為完整的自然語言句式描述（非逗號標籤堆疊），展示生成進度骨架屏（Skeleton），生成成功後於預覽區展示圖片，並提供「儲存至收藏」與「投入抽獎池」勾選。

**Acceptance Scenarios**:
1. **Given** 使用者開啟背景生成介面，**When** 輸入背景場景描述並選擇風格模板後點擊生成，**Then** 系統組合出主體結構、氛圍光影與空間透視的完整句式，顯示生成動畫並呈現高清背景預覽圖。
2. **Given** 背景生成成功，**When** 使用者勾選「投入抽獎池」並點擊儲存，**Then** 該背景標記為 `in_gacha_pool = true`，同時加入使用者背景收藏庫與混合抽獎池。
3. **Given** 生成過程發生錯誤或超時，**When** 捕捉到例外，**Then** 顯示友善錯誤訊息並提供「重新生成」按鈕，不中斷應用程式。

### User Story 3 - 物體與裝飾圖片生成功能 (Priority: P3)

作為一名喜歡收集成就與裝飾物的使用者，我希望輸入「物件語意特徵」（例如：「發光的藍色能量水晶獎盃」或「像素風格多肉仙人掌」），系統透過物件專屬句式範本（著重獨立主體、邊緣乾淨銳利、純色去背陳列），生成具備透明背景（Alpha 通道）的獨立物體圖片，加入個人背包供後續佈置使用，並可選擇是否投入抽獎池。

**Why this priority**:
獨立物體是後續畫布合成的零件。物體與背景完全分開，透過句式描述明確要求獨立主體與純淨去背，確保透明通道裁切平滑無雜物。

**Independent Test**:
渲染 `ObjectGeneratorModal`，輸入「物件語意特徵」，點擊生成，驗證組裝後的 Prompt 採用句式明確要求主體獨立與邊緣清晰，生成後回傳帶有透明 Alpha 背景之圖片 URL 或 SVG，並正確加入使用者的物件背包（Inventory），支援「投入抽獎池」標記。

**Acceptance Scenarios**:
1. **Given** 使用者輸入物件語意特徵與選取類型，**When** 執行生成，**Then** 系統應用專屬物件句式產生具備透明背景的獨立物件圖片（PNG/WebP/SVG）。
2. **Given** 物件圖片生成完畢，**When** 預覽圖片，**Then** 背景呈現棋盤格透明校驗效果，確保無白邊雜物且可正常進行圖層疊加。
3. **Given** 使用者點擊「收進背包」，**When** 儲存成功，**Then** 該物件加入背包庫（`ItemCategory: "badge"` 或 `"prop"`），若勾選入池則同步擴充自創獎池。

### User Story 4 - 畫布排版與「放置」非破壞性 AI 融合 (Priority: P4) 🎨 核心視覺

作為一名追求視覺沉浸感的使用者，我希望在畫布上載入背景圖片，並在背景之上即時排版、拖曳物體作為視覺底稿；當我點擊「放置」時，透過免金鑰免費圖生圖模型（如 Pollinations.ai / HuggingFace）進行智能融合，自然融合背景與物體的光影、透視與材質；融合後以非破壞性方式保留底層各物體圖層，允許我隨時微調重新放置；若網路連線失敗，則自動保留 2D 畫布疊加成果。

**Why this priority**:
這超越了單純的 2D 貼圖，透過免費圖片 LLM / 圖生圖管線實現真實感光影整合，同時採非破壞性圖層管理，避免使用者因一次合成失去微調能力，並具備 100% 離線/弱網容錯降級能力。

**Independent Test**:
渲染 `VisualStudioCanvas`：載入背景圖，拖曳加入物件並調整坐標。驗證即時 2D 排版互動流暢。點擊「放置」按鈕，驗證發送 Image-to-Image 融合請求；模擬 API 成功時展示融合後的高清影像，同時檢驗畫布圖層狀態未被清空（仍可選取與拖曳）；模擬 API 失敗時驗證無縫保留 2D 畫布合成圖並給予提示。

**Acceptance Scenarios**:
1. **Given** 使用者選取一張背景圖，**When** 從背包點選物件添加至畫布，**Then** 物件在背景之上即時呈現，支援拖曳位移、縮放與旋轉作為排版底稿。
2. **Given** 排版完成，**When** 使用者點擊「放置」按鈕，**Then** 畫布捕捉當前排版畫面，發送至免金鑰免費圖生圖端點（Image-to-Image），產出背景與物件光影融合後的全新畫面，並呈現非破壞性成果預覽。
3. **Given** AI 融合完成後進入預覽，**When** 使用者返回編輯或移動任一物件，**Then** 各物件圖層的坐標、縮放與旋轉參數完整保留，支援微調後再次點擊「放置」重新融合。
4. **Given** 免費圖生圖端點發生超時或網路失敗，**When** 捕捉到例外，**Then** 系統自動降級保留原生 2D 畫布合成影像，並提示「AI 融合暫不可用，已為您保留 2D 精準合成圖」，支援匯出與儲存。
5. **Given** 最終影像生成完畢（無論為 AI 融合圖或 2D 備援圖），**When** 使用者點擊「套用為主題」，**Then** 自動將該圖設定為應用程式桌面背景。

### User Story 5 - 隱藏成就零洩漏、無預警驚喜彈窗與焦慮推播門禁 (Priority: P5) 🛡️ 心理約束

作為一名在深度工作或反思的使用者，我希望未解鎖的隱藏成就在介面上絕對無痕跡（防 FOMO），當達成隱藏條件時以驚喜彈窗呈現；但在我處於焦慮或疲憊狀態時，系統絕不主動對我推播抽獎促銷誘惑。

**Why this priority**:
整合原 M3.11 SPEC 之心理健康鐵律：M3.11.3 隱藏成就零 UI 洩漏、M3.11.4 驚喜彈窗排隊佇列，以及 RISK-09 焦慮狀態主動推播抑制門禁 [CLAUDE.md 第二條, R09 §3.3]。

**Independent Test**:
- 檢驗 `AchievementGrid` 傳入未解鎖之 `hidden: true` 成就，驗證 DOM 中 0 洩漏（無佔位符、無問號）。
- 模擬 WebSocket `HIDDEN_ACHIEVEMENT_UNLOCKED` 事件，驗證 `SurpriseModal` 即時彈出，且多事件依序排隊不疊加。
- 傳入 `implicitState: { label: "anxiety" }` 給 `GachaPromotion`，驗證橫幅返回 null 徹底不渲染。
- 渲染 `DrawChallengeButton`，驗證點擊抽取 M4.11 ZPD 挑戰任務，介面嚴禁 XP 質押選項。

**Acceptance Scenarios**:
1. **Given** 成就資料庫中存在未解鎖之隱藏成就，**When** 渲染成就面板，**Then** 任何清單、網格或進度條均不出現該成就的任何佔位或暗示。
2. **Given** 收到 WebSocket 隱藏成就解鎖廣播，**When** 目前無其他彈窗，**Then** 立即以全域驚喜彈窗（`SurpriseModal`）呈現；若當前彈窗未關閉，則依序排入佇列等候。
3. **Given** 使用者隱性情緒標記為 `anxiety`、`avoidance` 或 `depression`，**When** 系統評估促銷展示，**Then** 完全禁止展示抽獎邀請橫幅。
4. **Given** 使用者點擊「🎲 抽挑戰」，**When** 向 M4.11 請求 ZPD 延伸任務，**Then** 展示挑戰內容，且介面絕無 XP 質押（Stake）輸入或選項 [RISK-07]。

### Edge Cases

1. **免費 AI 端點連線超時與頻率限制**：
   - 當免費圖生圖服務（如 Pollinations / HuggingFace）遭遇尖峰排隊或網路連線超時（> 10 秒）時，系統自動中止請求並平滑切換回 2D 畫布合成圖，保證零介面凍結。
2. **自創混合獎池為空保護**：
   - 當使用者切換至「自創混合池」但尚未生成或投入任何自創作品時，系統自動平滑切回「官方精選池」並給予友善提示，避免空獎池引發例外。
3. **透明通道合成鋸齒與穿孔**：
   - 匯出合成影像與送交圖生圖前，確保 Canvas Compositing 採用正確的 `globalCompositeOperation: "source-over"` 與平滑抗鋸齒演算法，防止物體邊緣泛白或失真。
4. **非破壞性圖層記憶體清理**：
   - 編輯器在生成 AI 預覽時，若使用者重試多次，內部自動釋放舊預覽的 Object URL / Base64 資源，避免記憶體洩漏。
5. **連續抽獎防連點與滑動冷卻**：
   - 抽獎按鈕在請求中鎖定防止重複扣款；連續 5 次抽獎後滑動視窗鎖定 60 分鐘。
6. **離線環境備援**：
   - 當無網路時，系統提供 6 款內建風格背景與 12 款透明物件，畫布 2D 排版與合成功能 100% 離線可用。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001 (抽獎介面)**: 系統必須提供 `GachaDrawButton` 元件，顯示單次抽獎費用（預設 100 XP）與使用者即時 XP 餘額。
- **FR-002 (費用門禁)**: 使用者 XP 不足時，抽獎按鈕必須禁用並提示「需要 100 XP（餘額不足）」。
- **FR-003 (防沉迷滑動視窗)**: 系統必須提供 `useDrawRateLimit` Hook，以 60 分鐘滑動時間視窗記錄抽獎次數；滿 5 次後強制鎖定按鈕並顯示剩餘冷卻時間。
- **FR-004 (L1 即時開獎)**: 抽獎成功後，系統必須透過 L1 即時通道（`deferStrategy: "immediate"`）於畫面彈出 `GachaResultToast`，展示抽得的背景或物件，具備稀有度光效。
- **FR-005 (混合獎池與入庫)**: 抽得之背景或物件必須自動寫入使用者個人收藏庫；抽獎系統支援「官方精選池」與「自創混合池」模式切換，使用者自創生成項目支援設定 `in_gacha_pool: true` 投入混合池。
- **FR-006 (背景生成器與句式增強)**: 系統必須提供 `BackgroundGenerator` 元件，支援輸入「背景場景描述」（Scene Prompt）與風格模板，Prompt 增強模組採用現代 LLM 具體自然語言句式（描述環境光影、空間層次與材質氛圍，嚴禁堆疊標籤），生成獨立背景圖片，並提供「投入抽獎池」選項。
- **FR-007 (物體生成器與去背句式)**: 系統必須提供 `ObjectGenerator` 元件，支援輸入「物件語意特徵」（Semantic Features），Prompt 增強模組採用物件專用具體句式（強調居中主體、純淨無雜物單色背景、銳利輪廓），生成具備透明背景（Alpha 通道）之獨立物體圖片，並提供「投入抽獎池」選項。
- **FR-008 (畫布排版底稿)**: 系統必須提供 `VisualStudioCanvas` 互動式編輯器，支援載入背景圖片作為底圖，並在背景之上即時排版拖曳物體圖片作為底稿。
- **FR-009 (非破壞性「放置」AI 圖生圖融合)**: 編輯器必須提供「放置」按鈕，將當前 2D 底稿發送至免金鑰免費服務（如 Pollinations.ai / HuggingFace 免費端點）執行 Image-to-Image 圖生圖融合，且完成後保留底層各物體圖層（坐標/大小/角度）不被破壞性合併。
- **FR-010 (AI 融合容錯降級與自訂主題庫)**: 若圖生圖服務失敗、超時或無網路，系統必須自動降級並保留 2D 畫布疊加成果；畫布編輯完成之場景支援儲存至本地自訂主題庫（`CustomThemeScene`）、一鍵套用為 coOS 桌面主背景，並支援單次 PNG/WebP 檔案下載匯出。
- **FR-011 (隱藏成就零洩漏)**: `AchievementGrid` 必須完全過濾未解鎖之隱藏成就（`item.hidden && !item.unlocked_at`），DOM 中不得渲染任何節點或問號佔位符。
- **FR-012 (驚喜彈窗佇列)**: 全域 WebSocket 監聽 `HIDDEN_ACHIEVEMENT_UNLOCKED` 事件，以 `SurpriseModal` 展示無預警驚喜；若有複數事件則以先進先出（FIFO）佇列排隊逐一呈現。
- **FR-013 (焦慮推播門禁)**: 主動抽獎促銷橫幅（`GachaPromotion`）必須接收使用者隱性狀態；當狀態為 `anxiety`、`avoidance` 或 `depression` 時完全不渲染。
- **FR-014 (ZPD 抽挑戰)**: 提供 `DrawChallengeButton` 抽取動態 ZPD 任務，介面嚴格禁止 XP 質押功能。
- **FR-015 (事件遙測)**: 抽獎、背景生成、物件生成、AI 放置融合與驚喜彈窗事件必須記錄至 M0.4 `raw_tracking_logs`。

### Key Entities

- **VisualItem (背景或物件項目)**:
  - `id`: 字串，唯一識別碼。
  - `name`: 顯示名稱。
  - `category`: 類別（`background` | `badge` | `theme` | `prop`）。
  - `rarity`: 稀有度（`common` | `rare` | `epic` | `legendary`）。
  - `image_url`: 圖片資源路徑或 Base64 / SVG 資料。
  - `has_transparency`: 布林值，物體為 true，背景為 false。
  - `scene_description`: 可選字串，背景專用場景描述。
  - `semantic_features`: 可選字串，物件專用語意特徵。
  - `is_user_generated`: 布林值，是否為使用者自訂生成作品。
  - `in_gacha_pool`: 布林值，是否已投入抽獎池供抽取。
  - `hidden`: 布林值，是否為隱藏成就。
  - `unlocked_at`: 可選時間字串，解鎖時間。
- **CanvasLayer (畫布圖層實體)**:
  - `id`: 圖層唯一識別碼。
  - `item_id`: 對應的物體 ID。
  - `image_url`: 圖層圖片路徑。
  - `semantic_features`: 該物體之語意特徵。
  - `x`, `y`: 數值，畫布坐標。
  - `scale`: 數值，縮放比例。
  - `rotation`: 數值，旋轉角度。
  - `zIndex`: 整數，堆疊層次。
- **CanvasState (畫布總狀態)**:
  - `background`: 可選之背景圖片物件。
  - `layers`: `CanvasLayer[]` 陣列。
  - `selectedLayerId`: 當前被選取正在編輯的圖層 ID。
  - `harmonized_preview_url`: 可選字串，AI 融合後的非破壞性成果預覽圖。
  - `is_preview_mode`: 布林值，是否處於成果預覽中。
- **CustomThemeScene (自訂主題場景實體)**:
  - `id`: 場景唯一識別碼。
  - `name`: 場景名稱。
  - `created_at`: 建立時間。
  - `canvas_state`: 畫布狀態（底圖與圖層坐標）。
  - `final_image_url`: 最終 AI 融合或 2D 成果圖 URL。
  - `is_active_theme`: 是否為當前 coOS 桌面套用之主背景。
- **HarmonizeResult (AI 圖生圖融合結果)**:
  - `image_url`: 融合後生成的高清圖片 URL 或 Base64。
  - `is_fallback`: 布林值，是否為 2D 畫布降級產物。
  - `provider`: 字串（`"pollinations"` | `"huggingface_free"` | `"canvas_2d_fallback"`）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001 (開獎即時性)**: 抽獎成功後，開獎 Toast 於 API 回傳後 100ms 內即時彈出，不經任何工作斷點延遲。
- **SC-002 (防沉迷鎖定精準度)**: 連續抽獎達 5 次時，按鈕 100% 正確進入冷卻禁用狀態，且不發送多餘網路請求。
- **SC-003 (具體句式生成精確度與獎池標記)**: 背景生成採用具體場景句式，物件生成採用獨立去背句式（嚴禁標籤堆疊）；支援自由勾選 `in_gacha_pool` 擴充獎池。
- **SC-004 (非破壞性 AI 放置融合與雙軌降級)**: 點擊「放置」觸發 Image-to-Image 融合；成功時產出光影一致之合成影像且底層圖層保留率為 100%；在模擬 500 錯誤或超時情況下，100% 自動無縫降級回傳 2D 畫布合成圖。
- **SC-005 (隱藏成就零洩漏)**: 自動化 DOM 查詢中，未解鎖之隱藏成就相關字串、問號佔位符或元素洩漏率為 0%。
- **SC-006 (焦慮門禁抑制率)**: 處於焦慮隱性心理狀態標記時，主動推播邀請橫幅渲染抑制率為 100%。
- **SC-007 (測試驗證通過率)**: 模組所有單元與組件整合測試全部通過（100% 綠燈）。

## Assumptions

- **免費 AI 資源端點**: 
  - 圖片生成與「放置」圖生圖融合採用免金鑰公共端點（如 Pollinations.ai 預設端點或 Hugging Face 公開免金鑰模型端點）。
  - 零設定門檻：使用者無需申請或配置付費 API Key 即可開箱即用。
  - 弱網與離線韌性：任何外部 API 異常皆保證退回純前端 2D 畫布合成，功能永不中斷。
- **現代生圖句式原則**: Prompt 範本遵循 FLUX / SDXL 現代架構，由主體描述、環境細節與材質構成完整連貫語句，揚棄舊式標籤贅詞。
- **非破壞性排版原則**: 點擊「放置」不會清除圖層資料，使用者享有完全的重試與微調自由度。
